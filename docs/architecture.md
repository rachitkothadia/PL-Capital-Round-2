# Architecture and trust boundaries

One `PortfolioAgent.answer_question()` serves CLI, TUI and evaluator. Presentation does not run financial arithmetic. The model only interprets questions, selects a typed tool and proposes SQL or a portfolio identifier. Financial values come from SQLite or Decimal arithmetic over SQLite holdings.

Initialization is the only relational write path: source fingerprint → locked temporary database → supplied schema → typed CSV insertion → constraint/FK/integrity verification → closed handles → atomic replacement. Existing manifests and changed sources are checked explicitly. Normal questions cannot rebuild an existing database.

Each SQL call independently validates a SQLite AST and opens its own read-only connection with authorizer, progress/step deadline, function/table restrictions and output budgets. Bindings are declared typed scalars. An invalid plan can trigger one bounded model correction. It is never executed as Python or shell. Audit projection checks enforce denominators and percentage conventions only for the narrow named-sector market-value contract; unrelated analytical shapes retain their requested precision. Unrequested rounding of computed averages is rejected before execution and can use the existing correction path. These checks contain no reference answers.

Graph ingestion accepts only trusted SQLite metadata and uses parameterized MERGE. Retrieval accepts text terms, not executable Cypher, and uses fixed read-only traversals. Graph outages preserve real SQLite metadata retrieval. Fingerprinted graph namespaces prevent changed snapshots from silently reusing old metadata. Native clients are lazy, optional and explicitly closed.

Provider plans use required fields, forbidden extras and a strict JSON schema. Numeric SQL parameter values use JSON number rather than an overlapping integer/number union, which was rejected by the live API and corrected after diagnosis. Calls are nonstreaming, temperature zero, token/time bounded, with two SDK retries. Operational traces show real actions and tool evidence; private model reasoning is never requested for display.

TUI analysis and evaluation run away from the UI event loop. A busy guard prevents conflicting concurrent questions and model/context changes. History, session list and timeline are bounded; there is no automatic transcript upload. Answers and compact evidence precede collapsed execution details; raw diagnostics remain opt-in. Theme variables cover the registered dark/light palettes and code blocks. Clipboard and export are separate actions: accepted SQL is passed through fixed native-backend argument arrays using stdin; lack of native confirmation exposes manual SQL and Save SQL. Export writes exclusive generated files beneath the cache with safe serialization and credential redaction.

The independent evaluator calls the actual agent, then compares against separate SQL references and separately aggregated exposure references. Production planning never reads the ground-truth fixture. Equivalent aliases are allowed; extra/missing columns, rows and duplicate counts are not flattened away. Reports scrub credentials and are written atomically with private POSIX permissions where supported (Windows inherits parent-directory ACLs).

The separate advanced challenge module compares twenty trusted SQL references with independent Python grouping/set/Decimal/time-series calculations. Only explicit evaluation commands load those references. Its five outcome statuses distinguish verified matches from failed, unsupported, inconclusive and unrun requests; saved-answer rescoring does not create new live calls.

Gemini and Groq share the same strict Plan model and local execution boundary. Settings infer the provider from a validated model ID and choose only its corresponding private key. Cross-provider switches close the old client before constructing a new one. Gemini uses fixed-host native generateContent requests with the key in a header, never a URL. The client bounds input/output, suppresses thought parts, rejects incomplete/invalid plans, retries only transient errors within bounds, honors retry delay instructions, and reports billing/auth failures without retrying or silently selecting Groq. Reports identify the provider actually used.
